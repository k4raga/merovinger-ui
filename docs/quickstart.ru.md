# Быстрый старт

Используйте Python 3.13 и виртуальное окружение. Из клона репозитория:

~~~console
python -m venv .venv
~~~

В POSIX-оболочке активируйте окружение командой `source .venv/bin/activate`,
в PowerShell — `.venv\Scripts\Activate.ps1`, затем выполните:

~~~console
python -m pip install .
~~~

## Зарегистрируйте симбиотический интерфейс

[Форма и редактор слоёв](../examples/symbiotic/main.py) — два независимых
компонента на основе `InteractionDefinition`. Из корня репозитория запустите
один из примеров.

```console
python examples/symbiotic/main.py form
python examples/symbiotic/main.py layers
```

Подключите описание вызовом `runtime.attach_interaction(parent, definition=definition)`.
Оно связывает типизированное состояние взаимодействия, исходные предметные
ссылки, семантические узлы сцены и их действия. SDK управляет вводом в сцене
и публикует её текущую версию. Оба примера используют общие API рантайма,
а редактор добавляет собственные слои, выделение и преобразования.

Адаптер агента открывает ход через `session.prepare_turn(request_id)`.
Снимок содержит состояние и разрешённые действия. Передайте `frame=True`,
когда модели нужен кадр этой сцены. Выполните действие через
`session.invoke_tool(request_id, offer_id, call_id, slot, arguments)`
и проверьте результат этого вызова. После перехода получите новый снимок.
В конце хода вызовите `session.finish_turn(request_id)`.

## Существующие интеграции AppBridge

Пример AppBridge подходит приложениям, которые используют прежний API привязки контролов.

~~~console
python examples/ui_agent/main.py --smoke --report .runtime/demo.json
~~~

Окно выполнит одно взаимодействие с локальным агентом и закроется. JSON-отчёт
содержит результат и состояние завершения runtime. Учётная запись провайдера
не нужна. Скрипт создаёт временную SQLite-базу, если не задан
`--database ABSOLUTE_PATH`. Для воспроизводимого первого запуска выберите новый путь.

## Опишите один раз

[Полный скрипт](../examples/ui_agent/main.py) — исполняемый пример.
Предметная модель задаётся обычным Registry; команда возвращает Patch:

~~~python
@domain.entity("board")
class Board:
    title: str
    enabled: bool
    items: Owned[Item]

@domain.command("set_enabled")
def set_enabled(ctx, board: Ref[Board], enabled: bool):
    return Plan(Patch(updates=(Update(board, {"enabled": enabled}),)))
~~~

`UiRuntime.open(registries=..., path=..., initial_patch=..., command_policy=...)`
владеет исходным runtime состояния, ядра и SQLite. Приложение задаёт своего
пользователя и политику команд; пример разрешает только две объявленные локальные
UI-команды. Открытие runtime не создаёт QApplication.

## Свяжите нативные контролы

Создайте QApplication приложения, родительский виджет и QBoxLayout.
`runtime.attach(parent, declarations=..., widgets=...)` возвращает AppBridge.
Необязательное сопоставление связывает объявленные пути с поддерживаемыми
существующими виджетами. Без него контролы будут созданы библиотекой.

`Action(command_id, arguments)` связывает контрол с существующей командой.
`INPUT` подставляет типизированное значение события. Поля используют `FieldRef`,
списки — `CollectionRef`. Второй копии предметного состояния в привязках нет.

Для представления только для чтения задайте `readonly=True` и объявления без
Actions. Локальные черновики, фокус и выбор могут меняться; предметные команды
в таком представлении недоступны.

## Передайте агенту пакет

`observe_for_model(destination=Destination(...))` возвращает владельца
ожидающей операции. Вызывайте `poll()` из обычного таймера приложения.
После готовности `take()` возвращает один пакет с контекстным менеджером:
`context_json`, `images`, `cut` и `visual_status`.
Каждое изображение содержит байты `png` и метку исходного захвата.

Ваш адаптер получает данные и выбирает объявленное действие. Используйте
`invoke_tracked`, чтобы обработать результат конкретного вызова в цикле Qt:

```python
def on_result(result):
    if result.outcome == "committed_local":
        show_saved(result.invocation_id)
    elif result.outcome == "failed_no_effect":
        show_refusal(result.error)
    else:
        show_status(result.outcome)

operation = bridge.invoke_tracked("enabled", False, on_result=on_result)
```

`operation.invocation_id` совпадает с `result.invocation_id` в каждом уведомлении.
`operation.accepted` сообщает о приёме команды, а `operation.intake` содержит
ту же строку, которую возвращает существующий `bridge.invoke(path, value)`.
`operation.result` равен `None` до первого результата, затем хранит последнее
полученное значение.

- `committed_local` содержит исходную квитанцию ядра о подтверждённой локальной записи.
- `failed_no_effect` означает отказ или подтверждённый откат и содержит код ошибки.
- `unknown` означает, что исход пока установить не удалось. При `final=False`
  по этому же вызову может прийти обновление. `final=True` отмечает последнее
  уведомление объекта операции.
- `approval_required` и `pending_external`, когда их возвращает ядро,
  содержат исходную квитанцию об ожидании одобрения или внешнего результата.

Необязательная функция вызывается асинхронно в потоке Qt и получает последнее
значение, если до уведомления пришло несколько обновлений. Оставьте цикл Qt
запущенным. Локальный агент примера проверяет контекст и PNG после изменения.

Черновик редактора отделён от сохранённого поля. Прямой вызов команды
не перезаписывает несохранённый локальный черновик молча.

## Завершите принадлежащие вам ресурсы

Закройте каждый пакет и ожидающее наблюдение. Сохраняйте работающий цикл Qt,
повторяя `bridge.close()` до результата `True`, затем вызовите `runtime.close()`.
Если кодировщик на CPU ещё работает, завершение может оставаться незавершённым:
отмена не доказывает физическую остановку. Заимствующий сервис захвата bridge
может удерживать владельца до своего закрытия.

Merovinger не закрывает QApplication приложения, его основное окно
или посторонних участников цикла событий.
